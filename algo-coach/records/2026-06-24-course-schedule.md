# 课程表 (Course Schedule)

LeetCode 207 | 归档: 2026-06-24 | 状态: 逻辑校验未完成

## 当前理解

- 课程可以抽象为点，先修关系可以抽象为有向边
- 无法完成全部课程的根因是依赖图中存在环
- 采用“先修课指向后续课程”的方向时，入度表示一门课尚未满足的先修课数量
- 入度为 `0` 的课程可以进入待学习队列
- 学完一门课后，它指向的后续课程入度减 `1`；减到 `0` 时加入队列
- 孤立课程初始入度为 `0`，也应进入队列
- 多门入度为 `0` 的课程先处理哪门不影响最终是否能完成全部课程
- 最终可以通过已处理课程数是否等于 `numCourses`，或是否仍有无法归零的入度，判断是否存在环

## 当前方案

对 `numCourses = 3`、`prerequisites = [[1,0],[2,0],[2,1]]`：

1. 建立入度数组，遍历依赖关系，将每条记录的课程入度加 `1`
2. 把入度为 `0` 的课程加入数组或队列
3. 扫描依赖关系，消除已完成先修课对应的边，并减少后续课程入度
4. 后续课程入度变为 `0` 时加入待处理集合
5. 没有可处理课程但仍有剩余依赖时，判断存在环

## 逻辑校验中发现的问题

1. **集合语义混淆**：当前 `array` 同时承担“所有已经学过的课程”和“当前等待处理后继的课程”两个含义，可能导致旧课程重复参与依赖消除
2. **课程 2 过早入队**：课程 2 的初始入度为 `2`；处理 `0 -> 2` 后只会降到 `1`，必须再处理 `1 -> 2` 才能入队
3. **环的判断时机不够精确**：一轮没有产生新的入度 `0` 课程不一定代表存在环；必须是待处理队列已经为空，同时仍有课程未完成
4. **反复扫描并删除边的实现风险**：遍历 `prerequisites` 时同步删除元素，容易跳过边或产生索引错误

## 当前停点

需要明确区分：

- 所有已经完成的课程
- 当前刚刚可以学习、等待处理其后继的课程
