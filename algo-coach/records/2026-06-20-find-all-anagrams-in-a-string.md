# 438. 找到字符串中所有字母异位词

日期: 2026-06-20 | 状态: 已推导（待逻辑校验/判题）

## 核心洞察（一句话）

异位词判断是无序的严格计数匹配；因为窗口长度固定为 `len(p)`，每次滑动只需更新移出字符和移入字符，并维护有多少类字符刚好满足需求。

## 追问阶段卡点与突破

1. **从 76 迁移滑动窗口框架**  
   这题建立在 `76. 最小覆盖子串` 的理解上：目标仍然无序，所以不能按字符顺序匹配，而要把 `p` 转成需求计数表。

2. **连续性与固定长度**  
   需要找的是 `s` 中的连续子串。和 76 不同，438 的窗口长度固定为 `len(p)`；窗口中不允许多出任何字符，也不允许缺少任何字符。窗口合法性不是“至少覆盖”，而是“计数完全相等”。

3. **多一个字符必然挤掉另一个字符**  
   用 `s = "abcbac"`, `p = "abc"` 推演：窗口 `"bcb"` 中 `b` 多了一个，同时 `a` 少了一个。因为窗口总长度固定，如果某类字符多了，必然有另一类需求字符少了。

4. **不能只看总差值**  
   `a` 少 1、`b` 多 1 时，总差值可能抵消为 0，但窗口仍然不合法。因此要看每个字符各自的计数是否刚好满足，而不是维护一个粗糙的总差值。

5. **固定窗口里的 `valid` 会双向变化**  
   `valid` 表示有多少种字符的 `window[c] == need[c]`。和 76 相比，438 中移入或移出字符都可能让某类字符从不满足变成满足，也可能从满足变成不满足。处理每个字符计数变化时，需要比较变化前后是否满足需求。

## 用户复盘

这道题建立在 76 的基础上，核心仍然是无序性，所以可以建立需求表和窗口表。

更准确地说，438 和 76 都要求连续子串；438 的额外约束是窗口长度固定为 `len(p)`，并且窗口中不允许存在任何多余元素。判断方式也从 76 的“至少覆盖”变成了“严格元素计数完全一致”。

因此 `valid` 的维护方式也更严格：不是简单增减，而是每次字符计数变化时判断该字符是否从“不满足”变成“满足”，或从“满足”变成“不满足”。
