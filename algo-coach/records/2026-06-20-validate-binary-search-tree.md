# 验证二叉搜索树 (Validate Binary Search Tree)

LeetCode 98 | 归档: 2026-06-20 | 状态: 已推导（待判题）

## 题目陷阱

二叉搜索树的约束不是只比较当前节点与左右孩子。一个节点还必须满足所有祖先根据路径方向留下的范围限制。

例如：

```text
      10
     /
    5
     \
      12
```

`12 > 5`，只看当前节点和父节点没有问题；但 `12` 位于根节点 `10` 的左子树中，所以还必须满足 `12 < 10`，该树并不是合法二叉搜索树。

## 本轮思路与校正

用户识别出除当前节点与左右孩子的直接比较外，还需要额外约束，并首先设想保存一个 `pre_root`，形成当前节点、孩子和前驱组成的最小判断结构。

这个结构仍然不够，因为非法节点可能违反更早祖先留下的限制，而不只是父节点的限制。

更准确的递归状态应该表达当前节点的完整合法区间：

```text
lower < node.val < upper
```

- 向左子树推进时，当前节点值成为新的上界
- 向右子树推进时，当前节点值成为新的下界
- 没有被当前节点收紧的另一侧边界继续继承自祖先

## 后续追问中的关键突破

1. **一度坚持只需要三个节点**：设想通过父节点、当前节点和子节点完成判断，认为不需要祖父或更早祖先
2. **先识别出难点集中在路径拐弯处**：一直向左或一直向右时，局部父子关系看起来足够；但根节点左子树中的右节点既要大于直接父节点，也必须小于更早祖先，因此合法条件实际是一个区间
3. **尝试用一个 `pre` 处理左右内拐**：计划定义左内拐和右内拐逻辑，在递归过程中额外保存一个变量。但如果 `pre` 只保存直接父节点，连续多次同向或拐弯后仍会丢失更早祖先留下的边界
4. **连续路径反例推翻三节点结构**：在 `20 -> 左 10 -> 右 15 -> 右 18 -> 右 25` 中，检查 `25` 时直接父节点是 `18`，局部关系成立，但 `25` 仍处于 `20` 的左子树，违反了上界 `20`
5. **最终从保存节点转向保存约束**：不再试图保留某一个祖先节点，而是把整条路径的历史限制压缩为 `lower` 和 `upper`

## 递归状态

递归处理的不只是当前节点，而是：

```text
check(node, lower, upper)
```

当前节点需要满足严格区间：

```text
lower < node.val < upper
```

继续递归时：

```text
左子树：check(node.left, lower, node.val)
右子树：check(node.right, node.val, upper)
```

每次只收紧一侧边界，另一侧边界原样向下传递，因此两个值能够代表整条祖先路径共同留下的约束。

## 用户复盘

这道题没有特别自然地想出来。最初陷入了一个惯性：看到树就想到链，并尝试通过当前节点、父节点和子节点之间的局部关系做间接比较。

真正的新认识是大小判断不一定要通过继续访问和保存更多历史元素完成，也可以把历史信息压缩成一个允许区间。递归向左移动时更新上边界，向右移动时更新下边界，再把两个边界继续传递下去。

一旦补上“操作区间”这一层，剩余递归逻辑就变得简单。

## 新的结构认识

当后续节点需要遵守整段历史带来的限制时，可以尝试把历史压缩成少量状态，而不是保存全部历史对象。
