# 翻转二叉树 (Invert Binary Tree)

LeetCode 226 | 归档: 2026-06-20 | 状态: 已推导（待判题）

## 核心洞察（一句话）

翻转整棵树可以拆成：交换当前节点的左右孩子，并对左右子树执行完全相同的翻转操作。

## 追问阶段卡点与突破

1. **最初类比为“分治和链表”**：二叉树和链表都由节点与指针构成，但本题处理的是具有 `left`、`right` 两个方向的树结构。分治视角是：翻转整棵树等于翻转两棵子树并交换它们的位置
2. **能够自行描述递归流程**：先交换当前节点的左右孩子，再分别递归处理交换后的左右子树。用只有左孩子的树完成手动模拟后，确认该流程可以处理单侧子树
3. **遗漏空树边界**：最初只在左右孩子都为空时停止，没有考虑传入的树本身就是 `null`，此时读取 `tree.left` 会出错。更统一的终止条件是“当前节点为 `null`”
4. **递归前交换和递归后交换都成立**：本轮先通过脑内模拟判断两者没有区别，随后用子问题同构解释：`Node(L, R)` 无论先交换还是先翻转子树，最终都是 `Node(invert(R), invert(L))`
5. **看到递归就误判为 `O(n log n)`**：`log n` 不是递归自动带来的。本题没有在每一层重新扫描全部节点，每个真实节点只被处理一次，因此时间复杂度是 `O(n)`
6. **曾把空间复杂度判断为 `2^n`**：混淆了递归调用总数与某一时刻同时存活的调用栈。不同分支会依次执行并释放，调用栈同时保留的只是一条从根到当前节点的路径，因此空间复杂度取决于树高 `h`
7. **时间与空间使用不同尺度**：时间统计所有递归调用的总工作量；空间统计某一时刻尚未返回的最大调用深度

## 用户复盘

这道题本身比较简单。有链表指针和递归知识后，交换左右节点并对子树递归比较自然，主要遗漏了空树边界。

真正的卡点是递归环境下的时间和空间复杂度。之前容易看到递归就想到 `log n`，但 `log n` 不是由“使用递归”产生的，而是由问题规模如何缩小、递归树每层做多少工作决定的。

本题需要访问整棵树中的每个节点，没有折叠掉需要处理的节点总量，因此时间复杂度为 `O(n)`，而不是 `O(h)` 或 `O(n log n)`。

空间方面，之前把递归产生的全部调用误认为会同时存储，甚至想到 `2^n`。实际上每个分支完成后，其栈帧会释放；某一时刻需要保留的是尚未返回的一条调用路径，因此空间复杂度看递归深度，也就是树高 `h`。

## 复杂度

- 时间复杂度：`O(n)`，每个节点访问一次
- 空间复杂度：`O(h)`，取决于递归调用栈的最大深度
- 平衡二叉树：`h = O(log n)`
- 极端退化成链表：`h = O(n)`

分析递归时可以固定区分：

> 时间：所有递归调用总共处理了多少工作？
>
> 空间：某一时刻最多有多少层调用还没有返回？
