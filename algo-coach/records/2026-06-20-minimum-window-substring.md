# 76. 最小覆盖子串

日期: 2026-06-20 | 状态: 已推导（待逻辑校验/判题）

## 核心洞察（一句话）

覆盖条件是无序的，不应按 `t` 的字符顺序匹配；应把目标转成需求计数表，用滑动窗口维护当前计数，并在合法时收缩左边界寻找最短窗口。

## 追问阶段卡点与突破

1. **把子串误看成子序列**  
   最初思路是按 `t[j]` 顺序在 `s` 中找字符，并记录若干索引。用 `s = "BAC"`, `t = "ABC"` 发现：正确答案是 `"BAC"`，但按 `A -> B -> C` 的顺序会找不到。因此这题不关心目标字符顺序，只关心窗口内字符数量是否覆盖。

2. **从字符位置转成统计匹配**  
   `t = "AABC"` 被转成需求表：`A:2, B:1, C:1`。窗口也维护一张现有表。合法性从“有没有按顺序匹配完”变成“窗口计数是否满足每个需求计数”。

3. **合法窗口为什么还要收缩**  
   对窗口 `"XBAAC"`，移走 `X` 后仍合法；继续移走 `B` 后不合法。由此得到规则：一旦窗口合法，就尝试移动左边界，直到再移一步会破坏合法性。每个合法窗口出现时都要记录最短答案。

4. **最佳窗口会不会被排除掉**  
   担心一开始就是最佳窗口，后续收缩会把它丢掉。突破点：在每次排除左边界之前，当前窗口已经合法，先记录答案，再尝试排除。因此即使后面扩张得到更长窗口，历史最短答案不会丢。

5. **`valid` 的维护规则**  
   用 `valid` 表示已经满足需求的字符种类数。加字符时，若 `window[c]` 刚好等于 `need[c]`，`valid += 1`；删字符时，若删除前 `window[c]` 刚好等于 `need[c]`，删除后会失去满足，`valid -= 1`。当 `valid == len(need)` 时，窗口合法。

## 用户复盘

这道题是一道滑动窗口的题，在理解上像是差速双指针。窗口不断改变，一般先向前移动，之后向内收缩，像“毛毛虫”一样推进。

这道题的目标判断是无序的，因此不需要从目标中的某个位置开始遍历匹配。按 `t` 的第一个元素一路匹配到最后一个元素，是错误方向。

因为具有无序性，所以可以将目标转化为统计。原问题就变成了统计数量的匹配问题：当窗口表向需求表接近并刚好满足某类字符时，计数加一；移除时如果导致偏离，计数减一；其余情况不变。通过这个规则判断什么时候满足条件，并在每次满足时记录当前最短窗口，直到遍历完成。
