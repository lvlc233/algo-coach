# 二分查找

## 核心洞察

每次砍掉一半，对数级收缩。30次比较覆盖10亿元素，暴力遍历需要5亿次。

## 追问卡点

| 卡点 | 突破 |
|------|------|
| 用"比最小小/比最大大"做排除，偏到边界检查 | 追问"在范围里了下一步做什么"，拉回搜索策略 |
| "折叠"概念模糊 | 给具体输入 `[1,3,5,...,19]` 找13，手动模拟每一步 |
| 计算中间索引时忘记除以2 | 自己验算发现算术翻车 |
| 对 log₂ 直觉偏差大，10亿说成7~9次 | 从 2^10=1024 往上翻，纠正到约30次 |

## 自行验证通过

- 向上取整和向下取整均能正确收敛
- `mid+1`/`mid-1` 边界更新不导致死循环
- 终止条件：`right < left`
- 重复元素对存在性判断无影响

## 关联

- 05-28 算法结构映射表已预判："搜索空间单调有序 → 二分"
- 双指针 → 二分：同是利用有序性做定向剪枝，从每次排除一个元素升级到每次排除一半空间
- 与单调栈区分：单调栈依赖瓶颈触发单调性，二分依赖搜索空间本身的单调性

## LeetCode 34 变体 — 最左/最右边界

### 核心思路

找最左：命中 target 时不停止，记录位置，假装值太大继续往左缩，直到区间为空。最右镜像操作。共两次独立二分，每次 O(log n)。

### 陷阱记录

1. **线性扫描**：找到任意 target 后左右线性扫找边界 → 全等数组退化为 O(n)
2. **递归重启二分 (O(log² n))**：每次命中 target 后在子区间重新启动一轮二分 → 全等数组做约 log n 轮独立二分，虽然比线性好，但仍非 O(log n)
3. **正确做法**：同一轮二分内调整条件继续走，不重启。命中 target 时只记答案、不 return，让区间继续收缩到底

## LeetCode 33 变体 — 搜索旋转排序数组

### 我的思路

其实就是在正常二分的基础上多加一个判断。原来的二分用左右边界判断目标值可能在哪边，现在数组被切了一刀，没法直接用，那就先判断哪半是干净的（`nums[left] <= nums[mid]` 说明左半没被截断、完全有序）。然后按正常二分的逻辑：目标值落在有序半的范围内，可能性就在那边；不在，就去另一半。其他跟正常二分一样去做就行。

### 感悟

之前学 704 时提的"可能性判断"（用边界排除不可达区间）是通用的，33 只是多了一步"先找有序半再判断归属"。用具体案例一步步模拟比抽象规则好用得多。

## LeetCode 153 变体 — 寻找旋转排序数组中的最小值

### 我的思路

取 `nums[0]` 做基准。先判断有没有逆序——没有就说明没旋转，直接取 `nums[0]`。有逆序就用 `nums[0]` 做二分目标：`mid >= nums[0]` 说明在左半有序段，最小值在右边；`mid < nums[0]` 说明已经到了右半，记下来然后继续往左找更小的。边界：没旋转的数组直接特殊处理。

## LeetCode 240 变体 — 搜索二维矩阵 II ⚠️重点复习

### 我的解法（交替横纵二分）

选对角线方向做交替二分：行二分找列边界 → 列二分找行边界 → 排除右侧和下侧矩形 → 收缩矩形后重复。复杂度 O(min(m,n) · log max(m,n))，极端宽高比时有优势。

### 标准解法（右上角法）

把矩阵看成逆时针转了 90°：从右上角开始，当前值 < target 就下移一行（排除整行），> target 就左移一列（排除整列）。每次 O(1) 砍一行或一列，复杂度 O(m+n)。本质同样是分区域找可能性，只是切法不同——对角判断 vs 逐行逐列排除。

### 感悟

关键不在哪种切法，在**视角**。一维二分每次砍一半是"中间点判断"，二维有两个方向，你需要一个能同时利用行单调和列单调的锚点。右上角恰好满足：往左递减、往下递增。
