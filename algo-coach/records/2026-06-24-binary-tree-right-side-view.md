# 二叉树的右视图 (Binary Tree Right Side View)

LeetCode 199 | 归档: 2026-06-24 | 状态: 逻辑校验中

## 当前思路

用户从题目的方向性出发，提出按右侧优先的深度优先顺序遍历二叉树，并维护一个按层存储结果的数组。

形成了两个关键观察：

1. 右视图结果长度等于树的最大深度
2. 如果同一层已经记录了右侧优先遍历时遇到的第一个节点，该层之后访问到的其他节点都应舍弃

具体策略是：

- 根节点从第 `0` 层开始
- 优先递归右子树，再递归左子树
- 到达某一层时，如果结果数组尚未记录该层，就写入当前节点
- 如果该层已经有值，则跳过写入，但仍继续递归其子树

用户分别用只有左子树、左子树中继续出现右孩子，以及左右子树同时存在的例子进行了模拟，得到 `[1, 2, 5]` 和 `[1, 3, 4]`。

## 判断正确的部分

- “每层只保留最右可见节点”的问题被转换成“右侧优先遍历时，每层只记录第一次访问到的节点”
- 不能只沿 `right` 指针前进；右子树缺失时，左子树中的节点仍可能出现在右视图中
- 外置结果数组并将层数作为递归状态，可以区分同一层的不同节点
- 数组应当对每一层只写入一次，而不是被后续左侧节点替换

## 当前伪代码中的问题

1. **遍历顺序命名不准确**：当前策略是“根 → 右 → 左”，属于右侧优先的前序式遍历，不是“右 → 中 → 左”的后序遍历
2. **记录对象写错**：伪代码在当前层为空时写入 `tree.right`，但需要记录的是当前访问节点；否则叶子节点或只有左孩子的情况无法正确记录
3. **缺少空节点边界**：进入递归后必须先处理当前节点为空的情况，否则会读取空节点的层或孩子
4. **递归没有传递层数**：调用左右子树时，需要让层数随深度增加；当前草稿中的 `see(tree.right)`、`see(tree.left)` 丢失了 `layer` 状态
5. **“可替换数组”与实际规则矛盾**：文字中称数组可替换，但模拟逻辑是该层存在值后跳过。为了保留最右节点，每层的结果应当是首次写入后不再覆盖
6. **示例叙述有一处节点编号笔误**：在 `1` 的左右孩子为 `2`、`3` 的例子中，优先访问的右节点应是 `3`，不是 `2`

## 核心洞察

右视图不一定来自每个节点的右孩子，而来自每一层按右侧优先访问时最先遇到的节点。
