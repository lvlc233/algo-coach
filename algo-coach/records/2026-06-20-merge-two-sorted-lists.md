# 合并两个有序链表 (Merge Two Sorted Lists)

LeetCode 21 | 归档: 2026-06-20 | 状态: 已推导（待判题）

## 核心洞察（一句话）

两条链表已经各自有序，因此每次只需比较当前两个节点，把较小者接到结果链表尾部，再移动对应指针。

## 追问阶段卡点与突破

1. **最初尝试直接交织两条原链表**：设想把当前较小节点直接指向另一条链表的当前节点，再交替修改两边的 `next`。在 `l1: 1 -> 4`、`l2: 2 -> 3` 中，先得到 `1 -> 2 -> 3` 后若再令 `2 -> 4`，原来的节点 `3` 就可能从结果链中断开。突破是把“读取原链表”和“连接结果链表”分开，由独立的尾指针维护已经合并好的部分
2. **一度跳过了仍未处理的当前节点**：第一次接入 `1` 后，误以为下一次比较的是 `3` 和 `4`。实际状态是 `l1` 已移动到 `4`，`l2` 仍停在 `2`，因此必须先比较 `4` 和 `2`；只有接入 `2` 后才轮到比较 `4` 和 `3`
3. **曾认为需要向后寻找比 `l1` 大的元素**：两条链表本身已经有序，所以不需要额外向后搜索。每轮只比较两个当前节点，就能确定合并结果的下一个节点；接入谁，就只移动谁的读取指针
4. **链表重连时要防止覆盖后续节点**：修改 `next` 后可能丢失原来的后续链条，需要区分负责遍历的指针与负责连接结果的尾指针
5. **画图比只在脑中追指针更可靠**：画出 `l1`、`l2`、结果入口和尾指针，可以直接看到当前比较对象与下一次连接位置
6. **中间结果链表让合并过程更清晰**：维护结果链表入口和尾指针 `tail`，每轮将较小节点接到尾部；节点通常直接复用，不需要复制节点或新建数组
7. **相等节点不需要同时接入**：任意选择一侧接入并移动对应指针，下一轮再处理另一侧，逻辑更统一

## 用户复盘

这道题有三个感悟：

1. 链表题中，对后续节点、前序节点的记录和覆盖是经典操作，需要特别留意
2. 处理链表连接关系时，画图会比只靠脑内模拟方便
3. 做合并排序类操作时，维护一个中间结果结构很方便

整体流程是：准备结果链表和尾指针，两个指针分别指向两条链表当前节点；每轮比较节点值，把较小节点接到结果尾部，并移动被选中的链表指针。若两个值相等，先接任意一个即可。某条链表为空后，把另一条剩余部分整体接到结果尾部。

## 用户重要思考

> 确实诶，确实，这样子就不用开多的数组了，链表处理空间复杂度确实好用。

链表可以通过复用原节点并修改 `next` 完成原地重组，额外空间通常能做到 `O(1)`。相应的代价是指针安全：覆盖 `next` 前若没有保留仍需访问的入口，可能直接丢失后续链条。

## 边界

- 一开始某条链表为空：直接返回另一条链表
- 两个值相等：接任意一侧都不影响有序性
- 某条链表提前结束：剩余链表无需继续比较，整体接入
