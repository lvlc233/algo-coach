# 问题结构 → 算法范式映射

归档: 2026-05-28 | 来源: 接雨水(42) / 最大矩形(84) 推导过程中总结

## 核心原则

问题的可剥削结构类型决定了最简可用算法的上界。

| 题目具有的性质 | 适用算法 | 典型复杂度 |
|---|---|---|
| 瓶颈单调触发 | 单调栈 | O(n) |
| 单调消去规则 | 双指针 | O(n) |
| 贪心选择性质 | 贪心 | O(n) / O(n log n) |
| 窗口合法条件单调 | 滑动窗口 | O(n) |
| 搜索空间单调有序 | 二分 | O(log n) |
| 问题可独立切割 | 分治 | O(n log n) |
| 最优子结构 + 重叠子问题 | DP | O(n^k) |
| 区间查询可结合 | 前缀和/树状数组/线段树 | O(1)/O(log n) |
| 只有合并没有拆分 | 并查集 | O(α(n)) |
| 图无环 + 偏序关系 | 拓扑排序 | O(V+E) |
| 边权非负 | Dijkstra | O(E log V) |
| 子问题对称可折叠 | 折半搜索 | O(2^(n/2)) |
| n ≤ 20 | 状压 DP | O(n·2ⁿ) |
| 流网络有对偶 | 最大流/最小割 | O(VE²) |
| 都没有 | 暴力穷举 | O(2ⁿ) |

## 分治的识别信号

不要只看题目中是否存在“比较”，而要问：

1. 能否把输入切成几个相对独立的部分？
2. 每个部分要解决的问题是否与原问题相同？
3. 局部答案能否高效合并成整体答案？
4. 拆分是否能让问题规模稳定缩小，最好接近均分？

满足这些条件时，分治才是强候选。能分治不等于应该分治；还需要判断它是否消除了朴素方法中的重复工作。

`148. 排序链表`：快慢指针支持近似均分；左右半段的排序与原问题同构；已有序的左右链表可以在线性时间合并，因此适合归并分治。

### 分治与动态规划

- 分治主要按输入结构切空间：子问题通常相对独立，分别算完后合并
- 动态规划主要按状态依赖切问题：子问题通常大量重叠，需要保存和复用结果
- 这不是绝对的形状边界；区间 DP 也按区间切，分治也不一定严格对半。更稳定的判断标准是子问题是否重叠

### 从 148 形成的个人判断过程

最初看到排序中的大量比较时，直觉是“比较可以作为小问题，因此大部分比较问题也许都可以分治”。这个判断过宽：比较只是操作，不一定是与原问题同构的子问题；寻找最大值同样包含比较，也能形式上分治，但线性扫描已经最优，分治没有消除额外的重复工作。

对 `148. 排序链表`，真正的小问题不是“比较两个元素”，而是“把一条更短的链表排好序”。判断链条是：

```text
整条链表需要有序
→ 左半和右半可以分别变成有序链表
→ 两个子问题仍然是“排序链表”
→ 两个局部有序结果可以线性合并
→ 快慢指针又能支持近似均分
→ 分治条件齐全
```

这次形成的感悟是：不能只问题目里有没有比较，而要寻找能够独立求解、与原问题同构、并且结果可低成本合并的小问题。还要继续判断分治是否比朴素方法减少了重复工作。

与动态规划对照时，第一反应是两者都在拆小问题。更精确的边界是：分治的左右子问题通常相对独立，分别算完后合并；动态规划的状态通常大量重叠，因此保存的不一定只是数值，也可能是布尔状态、方案数量或其他可复用结果。

## 关键洞察

1. **不是"算法选问题"，是"问题筛选算法"** — 题目有哪些性质，决定了哪些范式可用
2. **贪心是 DP 的子集** — 贪心能解的 DP 也能，但更慢；贪心需要更强的额外性质
3. **层次关系**：多个性质同时满足 → 多种算法可选，取最简
