# 反转链表 (Reverse Linked List)

LeetCode 206 | 归档: 2026-06-20 | 状态: 已推导（待判题）

## 核心洞察（一句话）

反转链表不是新建一条链，而是在原链表上逐个修改 `next` 指向；为了不丢失后续节点，必须先缓存原来的下一个节点。

## 追问阶段卡点与突破

1. **链表访问受 `next` 限制**：单链表只能沿当前节点的 `next` 向后访问，不能随机访问或自然回头，因此反转需要从头开始，边遍历边修改指针
2. **反转不是新建链表**：已反转区域和未处理区域都由原节点组成，没有复制节点；额外只保存几个指针变量，所以空间复杂度是 `O(1)`
3. **必须缓存后继，避免丢链**：修改当前节点的 `next` 前，要先保存原来的下一个节点，否则后续链条会失去入口
4. **每轮操作的本质**：保存后继、让当前节点指向前驱、更新已反转部分的头，再移动到原后继节点
5. **循环条件容易写错**：循环应判断当前节点是否为空，而不是判断缓存的后继是否为空；最后一个节点的 `next` 虽然为空，但该节点仍需要被反转

## 用户复盘

这题的核心是链表访问只能按照指向关系来，所以第一直觉就是从首个元素开始。

反转过程中确实做了外部存储，但外部存储只保存几个指针，例如当前节点、前驱节点、缓存的后继节点。本质上只是保存已反转链表的头和继续访问原链表的入口，因此空间复杂度是 `O(1)`。

朴素想法是：断开当前操作元素与下个元素的链接，并使当前元素指向前一个元素。对应操作是：

```text
pre = null
cache = i.next
i.next = pre
pre = i
i = cache
```

其中 `cache = i.next` 很关键。如果先执行 `i.next = pre`，原来的后续链条就会丢失，之后无法继续访问。

这道题能用自然语言描述清楚，但写成伪代码时仍然容易遗漏边界，尤其是循环条件应该看当前节点 `i` 是否为空，而不是看 `cache` 是否为空。
