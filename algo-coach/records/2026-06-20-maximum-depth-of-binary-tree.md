# 二叉树的最大深度 (Maximum Depth of Binary Tree)

LeetCode 104 | 归档: 2026-06-20 | 状态: 逻辑闭合（待判题）

## 核心洞察（一句话）

先假设左右子树的最大深度已经求出，当前树的最大深度就是两者较大值再加上根节点这一层。

## 本轮推导

本轮开始自然产生了递归、分治或动态规划的联想。思考方式是：假设已经知道根节点之外两棵子树的最大深度，不再关心它们的具体形状，只判断父问题如何由两个子问题的结果组成。

例如：

```text
左子树最大深度：7
右子树最大深度：5
```

因为整棵树的最长路径会选择更深的左子树，并加上当前根节点这一层，所以整棵树的最大深度为 `8`。

由此识别出父问题的组合操作需要取左右子树深度的较大值。

## 结构认识

- 子问题是“求一棵更小子树的最大深度”，与原问题同构
- 左右子树相对独立，不存在大量需要缓存复用的重叠状态
- 因此当前思路更接近递归分治，而不是典型动态规划

## 后续逻辑校验

用户补全了递归流程：

```text
search(tree):
  if tree == null: return 0
  left_max = search(tree.left)
  right_max = search(tree.right)
  num = max(left_max, right_max) + 1
  return num
```

逻辑已经闭合：空节点深度为 `0`；分别递归求左右子树深度；选择较深的一侧；加上当前节点这一层；再将结果返回父节点。

## 复杂度卡点与突破

1. **最初把时间复杂度判断为 `O(h)`**：混淆了递归深度与总访问节点数。`O(h)` 描述的是某一时刻调用栈中保留的一条根到当前节点的路径，更接近空间复杂度
2. **随后又判断为 `O(log n)`**：平衡树高度约为 `log n`，但求最大深度仍需访问左右子树中的所有节点，不能只看树高
3. **最终区分时间和空间**：整棵树的每个节点都被访问一次，因此时间复杂度是 `O(n)`；递归栈最大深度取决于树高，因此空间复杂度是 `O(h)`
4. **理解最坏空间退化**：平衡树中 `h = O(log n)`；当二叉树退化成一条链时，`h = n`，调用栈需要同时保留整条路径，因此最坏空间复杂度为 `O(n)`

## 最终复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(h)`
- 平衡树空间：`O(log n)`
- 退化成链时的最坏空间：`O(n)`
