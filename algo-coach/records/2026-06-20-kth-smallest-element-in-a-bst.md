# 二叉搜索树中第 K 小的元素 (Kth Smallest Element in a BST)

LeetCode 230 | 归档: 2026-06-20 | 状态: 核心思路已复盘（提前停止未校验）

## 题目结构

二叉搜索树满足：

```text
左子树所有值 < 根节点 < 右子树所有值
```

因此按照“左子树 → 根节点 → 右子树”的顺序访问时，节点值会以从小到大的顺序出现。

会话使用以下例子说明第 `k` 小元素：

```text
    3
   / \
  1   4
   \
    2
```

对应的升序值为 `1, 2, 3, 4`。

## 后续追问与突破

1. **最初想到额外链表**：因为中序遍历会产生有序序列，第一反应是将访问结果保存下来。但目标只需要第 `k` 小，不必存储全部节点；按升序访问时只需维护访问计数
2. **一度混淆第 `k` 小和第 `k` 大**：用完整二叉树示意时先讨论了“第 4 大”，随后通过写出中序序列 `d, b, e, a, f, c, g`，确认第 4 个访问到的节点是 `a`
3. **理解必须先完成左子树**：左子树中的所有值更小，只有先按中序完成左子树，当前节点的访问序号才确定。但不需要保存左子树的节点，只需要每访问一个节点就令计数器加一
4. **把提前结束误解为关闭其他线程**：本题没有多个线程，而是一条递归调用链和尚未执行的分支。找到答案后需要保存“答案已找到”的状态，并让后续递归尽早返回
5. **明确需要两个核心状态**：`count` 表示已经按中序访问的节点数量，`answer` 保存第 `k` 小节点的值。只有答案无法判断当前访问序号，只有计数无法保存最终结果
6. **尝试让递归返回子树节点数**：伪代码中用 `left_num`、`right_num` 回传排名，导致中序结构复杂化。更直接的方式是让递归只负责“左 → 当前 → 右”的访问顺序，并共享计数状态
7. **递归边界判断错位**：最初判断 `node.left == null` 就返回，这会跳过没有左孩子但自身仍需访问的节点。正确的统一边界应检查当前 `node` 是否为空
8. **当前节点的计数顺序**：`count` 表示已经完成访问的节点数量，因此访问当前节点时要先执行 `count += 1`，再判断是否达到 `k`

## 当前中序骨架

```text
处理中序(node):
    如果 node 为空：结束

    处理中序(node.left)

    count += 1
    如果 count == k：
        记录 node.val

    处理中序(node.right)
```

这里不需要额外链表，也不需要为每个节点单独计算名次。中序访问的全局计数本身就是当前节点在升序序列中的位置。

## 用户复盘

这道题走了不少弯路。直觉上，为了找第 `k` 小元素，最初想先通过树的某种遍历把节点还原成一条链表，再在链表中查找。这个方案理论上可以实现，但会额外保存完整序列，提高空间开销。

之后意识到可以一边搜索一边计数。二叉搜索树的中序遍历天然按从小到大的顺序访问节点，因此在访问当前节点时更新计数；当计数等于目标 `k` 时，当前节点就是答案，不需要先构造完整链表。

本题暴露出的主要问题是：

1. 对二叉搜索树的有序性质以及前序、中序等遍历顺序的特点还不熟悉
2. 对递归中代码应该如何组织还不熟悉
3. 再次确认递归过程中可以使用外部或共享状态，记录跨递归调用持续变化的访问计数和答案

这次最重要的迁移是：当遍历顺序本身已经提供目标顺序时，可以在遍历过程中在线统计和提前命中，而不必先物化整个结果序列。
